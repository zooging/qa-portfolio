# QA-портфолио — Дмитрий Борисов

Публичные доказательства навыков Junior QA / AQA: API-автотесты, E2E, отчёты, баг-репорты и документация ручного тестирования.

> Проект собирается как тестовый запуск: полный цикл «идея → репозиторий → CI → отчёт → карточка в hh.ru» сжат до одной недели. Цель — проверить, что из плана работает в реальном поиске работы.

## Проекты

| # | Проект | Что показывает | Метрики |
|---|---|---|---|
| 1 | [API-автотесты Restful Booker](api-tests/README.md) | pytest + requests + jsonschema + Allure + GitHub Actions | 52 теста, 9 багов, 21 с |
| 2 | [E2E на Playwright](e2e-playwright/README.md) | логин, каталог, корзина, checkout, expect-assertions | 15 тестов, 7,7 с |
| 3 | [Manual QA по диплому](manual-qa/README.md) | тест-план, 50 проверок, 30 кейсов, 15 находок | 16 требований в трассировке |
| 4 | [Нагрузка на k6](load-tests/README.md) | p95, пороги ошибок, метрика ограничения стенда | p95 = 181 мс, 123/123 проверок |

## Что подтверждено на практике

- Публичный API отдаёт **500** на пропущенные обязательные поля и принимает невалидные даты/цены — 9 баг-репортов с шагами.
- Дипломное приложение содержит **реальные дефекты в бизнес-логике бронирования** — 10 подтвержденных ссылками на код, включая «отмена не сохраняется» и «редактирование создаёт дубликат».
- Публичный Restful Booker **ограничивает нагрузку уже при 2–3 VU** (`418 I'm a Teapot`) — найдено k6.
- Все автотесты проходят в CI на каждый push; отчёты доступны как артефакты.

## Структура репозитория

```text
qa-portfolio/
  api-tests/          # pytest + requests + Allure
  e2e-playwright/     # Playwright + Allure
  manual-qa/          # документация ручного тестирования
  load-tests/         # сценарий k6 и summary.json
  hh-ru/              # тексты карточек портфолио и правки резюме
  .github/workflows/  # 3 workflow: API, E2E, нагрузка
```
