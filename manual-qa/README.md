# Manual QA-пакет: мобильное приложение аренды спортинвентаря

Объект тестирования — дипломный проект [sport_equipment](https://github.com/zooging/sport_equipment) (Flutter + Firebase), учебный прототип 2025 года.

## Что лежит в папке

| Файл | Содержание |
|---|---|
| [test-plan.md](test-plan.md) | объём, риски, критерии старта/финиша, окружение |
| [checklist.md](checklist.md) | 50 проверок для smoke и регресса |
| [test-cases/](test-cases/) | 30 тест-кейсов по 5 модулям |
| [bugs/](bugs/) | 15 находок (10 подтверждены кодом, 5 дополнительных) |
| [traceability.csv](traceability.csv) | requirement → test case → defect → status |
| [test-report.md](test-report.md) | итоги, остаточные риски, выводы |

## Честный дисклеймер об источнике данных

Локально нет Flutter SDK и Docker, поэтому запуск приложения/эмулятора невозможен. Дефекты **`bugs/BUG-01..BUG-10` подтверждены чтением исходного кода** с указанием точного файла и строк: это не «гипотетические» ошибки, а реально существующие ветки кода, которые дают неверное поведение. Полный UI-прогон и скриншоты — следующий шаг при наличии билда; в отчёте это явно отражено как ограничение.

Требования взяты из ВКР (`3.2. Определение требований к системе`, строки 632–666) и README репозитория.
