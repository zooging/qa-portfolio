# BUG-05. Потеря минут при расчёте длительности и стоимости

| Поле | Значение |
|---|---|
| Severity | Medium |
| Priority | Medium |
| Статус | Open |
| Метод подтверждения | Анализ кода: `lib/features/booking/screens/booking_screen.dart:42-44, 114-118`; `lib/features/booking/widgets/booking_confirmation_dialog.dart:47,51` |
| Тест-кейсы | TC-BKG-08, TC-PRF-03 |

## Шаги воспроизведения (UI)

1. Выбрать начало 10:00, конец 11:45.
2. Посмотреть длительность и итоговую сумму, затем данные подтверждения.

## Фактический результат

Показывается «1 ч» и цена `pricePerHour × 1`, хотя в Firestore сохранятся `10:00–11:45` (1 ч 45 мин). Диалог подтверждения содержит те же несовпадающие данные.

## Ожидаемый результат

Либо расчёт по факту (1,75 ч), либо явно документированное правило округления до часа, единое для UI и БД.

## Доказательство в коде

```dart
_hours = _endDate!.difference(_startDate!).inHours; // дробная часть отбрасывается
if (_hours < 1) _hours = 1;
_calculateTotal(); // _totalPrice = widget.equipment.pricePerHour * _hours;
```

## Влияние

Расхождение между сохранёнными датами и суммой; ошибки в отчётах и претензиях.

## Рекомендация

Использовать `duration.inMinutes / 60` и единую функцию расчёта стоимости в сервисе, а не в виджете.
