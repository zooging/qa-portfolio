# BUG-07. Бейдж «Новые» не появляется, а при включении ломается парсинг брони

| Поле | Значение |
|---|---|
| Severity | Medium |
| Priority | Medium |
| Статус | Open |
| Метод подтверждения | Анализ кода: `lib/features/home/screens/owner_home_screen.dart:36-60, 94-100`; `lib/data/services/booking_service.dart:371`; `lib/data/models/rental_booking.dart:41-45` |
| Тест-кейс | TC-OWN-05 |

## Шаги воспроизведения (UI)

1. Создать pending-бронь.
2. Войти владельцем и открыть «Панель управления».

## Фактический результат

Бейджа «Новые» нет: обе карточки создаются без `equipmentId`, поэтому `hasNewBookings` всегда `false`. Если передать ID, стрим упадёт с `_CastError`: `RentalBooking.fromJson` ожидает `String` для `startDate`, а в Firestore пишется `Timestamp`. Ошибка подавляется через `error: (_, __) => false`.

## Ожидаемый результат

Бейдж виден при наличии pending-заявок, список заявок открывается без ошибок.

## Влияние

Владелец не видит новые заявки; скрытая ошибка парсинга маскируется как «нет заявок».

## Рекомендация

Передавать `equipmentId` в карточки, поддерживать `Timestamp` в `RentalBooking.fromJson`, логировать ошибки стрима вместо их подавления.
