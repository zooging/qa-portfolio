# BUG-01. Кнопка «Отменить» показывает успех, но не меняет статус брони

| Поле | Значение |
|---|---|
| Severity | High |
| Priority | High |
| Статус | Open |
| Метод подтверждения | Анализ исходного кода, `lib/features/booking/screens/booking_status_screen.dart:323-330` |
| Тест-кейс | TC-BKG-06 |

## Шаги воспроизведения (UI)

1. Создать бронирование и открыть «Статус бронирования».
2. Нажать «Отменить» → «Да, отменить».
3. Перезапустить приложение и открыть статус снова.

## Фактический результат

Показывается SnackBar «Бронирование отменено», но запись в Firestore не обновляется; после перезапуска статус снова `pending`.

## Ожидаемый результат

Статус меняется на `cancelled` в БД и на экране, equipment возвращается в `available`.

## Доказательство в коде

```dart
onPressed: () {
  // TODO: Implement cancel booking logic
  Navigator.of(context).pop();
  ScaffoldMessenger.of(context).showSnackBar(
    const SnackBar(content: Text('Бронирование отменено')),
  );
},
```

Рабочий метод `cancelBooking` существует в `lib/data/services/booking_service.dart:399-421`, но здесь не вызывается.

## Влияние

Пользователь уверен, что бронь отменена, но она остаётся активной и блокирует инвентарь.

## Рекомендация

Вызвать `cancelBooking(booking.id)`, дождаться результата и показывать SnackBar только при успехе; обработать ошибку.
