# Тест-кейсы: авторизация и регистрация

Формат: ID / требование / приоритет / предусловия / шаги / ожидаемый результат / статус.

### TC-AUTH-01 — Регистрация нового клиента
- **Требование:** FR-01 (ВКР, строка 636) · **Приоритет:** High
- **Предусловия:** пользователь с email `new.client@qa.test` отсутствует.
- **Шаги:** 1) Открыть «Регистрация». 2) Заполнить имя, email, пароль, роль «client». 3) Нажать «Зарегистрироваться».
- **Ожидаемо:** запись создана в `users`, пользователь вошёл, открыт главный экран.
- **Статус:** Planned (нужен стенд).

### TC-AUTH-02 — Вход с неверным паролем
- **Требование:** FR-02 (строка 637) · **Приоритет:** High
- **Предусловия:** пользователь `client@qa.test` существует.
- **Шаги:** 1) Ввести `client@qa.test` и `wrong-password`. 2) Нажать «Войти».
- **Ожидаемо:** понятное сообщение об ошибке, перехода в приложение нет.
- **Статус:** Planned. Связанный риск: A3 (некорректный маппинг сообщений об ошибке).

### TC-AUTH-03 — Регистрация с невалидным email и телефоном
- **Требование:** FR-01 · **Приоритет:** Medium
- **Шаги:** 1) Ввести email `abc`, телефон `abc`. 2) Нажать «Зарегистрироваться».
- **Ожидаемо:** inline-валидация обоих полей, запись не создаётся.
- **Статус:** Static: FAIL → A4 (валидация только по наличию `@` и непустоте).

### TC-AUTH-04 — Выход из аккаунта
- **Требование:** FR-02 · **Приоритет:** Medium
- **Предусловия:** пользователь вошёл.
- **Шаги:** 1) Открыть меню. 2) Нажать «Выйти».
- **Ожидаемо:** экран входа, сессия Firebase Auth очищена.
- **Статус:** Planned.
