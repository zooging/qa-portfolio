# BUG-002. Бронирование принимает checkout раньше checkin

| Поле | Значение |
|---|---|
| Severity | Major |
| Priority | High |
| Status | Open |
| Environment | https://restful-booker.herokuapp.com, 27.11.2026 |
| Тип | Бизнес-валидация дат |

## Шаги воспроизведения

1. `POST /booking` с телом:

```json
{
  "firstname": "Jim", "lastname": "Brown", "totalprice": 111, "depositpaid": true,
  "bookingdates": {"checkin": "2027-05-10", "checkout": "2027-05-01"},
  "additionalneeds": "Breakfast"
}
```

2. `GET /booking/{bookingid}` созданного бронирования.

## Фактический результат

`200 OK`, бронирование создано и сохранено с некорректным периодом: выезд на 9 дней раньше заезда.

## Ожидаемый результат

`400 Bad Request`, бронирование не создаётся, сообщение вида `checkout must be later than checkin`.

## Почему это важно

Нарушение доменного правила ведёт к неверным данным в БД и некорректной логике расчёта стоимости/доступности. В UI такой баг был бы виден сразу, на API — только при сверке данных.

## Тест-свидетель

`tests/test_negative.py::test_create_with_reversed_dates`

## Предложение по исправлению

Добавить проверку `checkout > checkin` на уровне валидации запроса и/или constraint в БД.
