# BUG-003. Строка вместо totalprice сохраняется как null

| Поле | Значение |
|---|---|
| Severity | Major |
| Priority | Medium |
| Status | Open |
| Environment | https://restful-booker.herokuapp.com, 27.11.2026 |
| Тип | Валидация типа данных |

## Шаги воспроизведения

1. `POST /booking` с `totalprice: "abc"` и остальными корректными полями.
2. Запомнить `bookingid` из ответа, выполнить `GET /booking/{bookingid}`.

## Фактический результат

Ответ: `200 OK`, в теле `"totalprice": null`. Значение цены потеряно без ошибки.

## Ожидаемый результат

`400 Bad Request` с сообщением, что `totalprice` должен быть числом.

## Почему это важно

Данные молча портятся: клиент думает, что бронирование создано корректно, но цена отсутствует. Далее это влияет на расчёты и отчётность.

## Тест-свидетель

`tests/test_negative.py::test_create_with_string_price`

## Предложение по исправлению

Включить проверку типа в JSON-схему запроса (`"type": "number"`, `"minimum": 0`) и отклонять невалидные значения до записи в БД.
