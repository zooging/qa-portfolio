# BUG-006. Для несуществующего бронирования UPDATE/DELETE возвращают 405 вместо 404

| Поле | Значение |
|---|---|
| Severity | Minor |
| Priority | Low |
| Status | Open |
| Environment | https://restful-booker.herokuapp.com, 27.11.2026 |
| Тип | HTTP-контракт / обработка ошибок |

## Шаги воспроизведения

1. `PUT /booking/99999999` с валидным телом и cookie `token=<валидный>`.
2. Повторить `PATCH` и `DELETE` с несуществующим ID.
3. Повторно удалить уже удалённое бронирование.

## Фактический результат

`405 Method Not Allowed`, тело `Method Not Allowed`.

## Ожидаемый результат

`404 Not Found` — ресурс не существует; повторный DELETE также может быть идемпотентным (204/404).

## Почему это важно

405 означает «метод не поддерживается ресурсом», тогда как поддерживаемый метод, применённый к отсутствующему объекту, — это 404. Клиент не может корректно обработать ситуацию.

## Тест-свидетель

`tests/test_booking_crud.py::test_put_nonexistent_booking_returns_404`

## Предложение по исправлению

Различать «нет записи» (404) и «метод запрещён» (405) на роутинге/в обработчике.
