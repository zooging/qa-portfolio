# BUG-005. Неверные учётные данные возвращают HTTP 200 вместо 401

| Поле | Значение |
|---|---|
| Severity | Major |
| Priority | High |
| Status | Open |
| Environment | https://restful-booker.herokuapp.com, 27.11.2026 |
| Тип | Авторизация / HTTP-контракт |

## Шаги воспроизведения

1. `POST /auth` с `{"username": "admin", "password": "wrong"}`.
2. Повторить с несуществующим пользователем и с пустым паролем.

## Фактический результат

`200 OK` и тело `{"reason": "Bad credentials"}` — успешный HTTP-статус при ошибке аутентификации.

## Ожидаемый результат

`401 Unauthorized` (или `403 Forbidden`) и сообщение об ошибке, но не 200.

## Почему это важно

Клиентские библиотеки и мониторинг определяют успешность по HTTP-коду. Из-за 200 ошибка логина может быть проигнорирована; это также вводит в заблуждение при разборе логов.

## Тесты-свидетели

- `tests/test_auth.py::test_wrong_password_returns_401`
- `tests/test_auth.py::test_unknown_user_returns_401`
- `tests/test_auth.py::test_empty_password_returns_401`

## Предложение по исправлению

Возвращать 401 при любых невалидных учётных данных, не различая «нет такого пользователя» и «неверный пароль» в ответе (во избежание user enumeration).
