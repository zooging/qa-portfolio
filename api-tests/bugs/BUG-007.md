# BUG-007. Фильтр `checkin` не возвращает существующие бронирования

| Поле | Значение |
|---|---|
| Severity | Major |
| Priority | High |
| Status | Open |
| Environment | https://restful-booker.herokuapp.com, 27.11.2026 |
| Тип | Поиск / фильтрация |

## Шаги воспроизведения

1. Создать бронирование с `checkin = 2027-03-01`, `checkout = 2027-03-05`.
2. Выполнить `GET /booking?checkin=2027-03-01`.
3. Повторить с `GET /booking?checkin=<дата>&checkout=<дата>`.

## Фактический результат

`200 OK` и пустой массив `[]`, хотя бронирование с такой датой существует. В связке с `checkout` результат тоже пустой.

## Ожидаемый результат

Список, содержащий `bookingid` созданного бронирования.

## Почему это важно

Клиент не может найти бронирования по дате заезда — ключевой сценарий для сервиса аренды. Дефект не виден в UI, если интерфейс фильтрует данные локально.

## Тесты-свидетели

- `tests/test_booking_search.py::test_filter_by_checkin`
- `tests/test_booking_search.py::test_filter_by_checkin_and_checkout`

## Предложение по исправлению

Проверить имя параметра в слое контроллера и условие SQL-запроса; добавить integration-тест на фильтр по дате.
