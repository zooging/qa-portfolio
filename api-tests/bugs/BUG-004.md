# BUG-004. Отрицательная стоимость бронирования принимается

| Поле | Значение |
|---|---|
| Severity | Minor |
| Priority | Medium |
| Status | Open |
| Environment | https://restful-booker.herokuapp.com, 27.11.2026 |
| Тип | Граничные значения / бизнес-валидация |

## Шаги воспроизведения

1. `POST /booking` с `totalprice: -5` и остальными корректными полями.

## Фактический результат

`200 OK`, бронирование создано с `totalprice: -5`.

## Ожидаемый результат

`400 Bad Request`: стоимость не может быть отрицательной.

## Почему это важно

Классический случай граничного значения: без проверки в API некорректные данные попадают в БД и могут привести к отрицательным суммам в биллинговых отчётах.

## Тест-свидетель

`tests/test_negative.py::test_create_with_negative_price`

## Предложение по исправлению

Добавить `"minimum": 0` в схему `totalprice` и проверку на уровне бизнес-логики.
