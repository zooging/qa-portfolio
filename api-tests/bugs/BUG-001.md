# BUG-001. POST /booking возвращает 500 при отсутствии обязательных полей

| Поле | Значение |
|---|---|
| Severity | Major |
| Priority | High |
| Status | Open |
| Environment | https://restful-booker.herokuapp.com, 27.11.2026 |
| Тип | Обработка ошибок / валидация входа |

## Шаги воспроизведения

1. Отправить `POST /booking` с заголовком `Content-Type: application/json`.
2. В теле передать валидный payload бронирования, но удалить одно из полей: `firstname`, `lastname`, `totalprice`, `depositpaid`, `bookingdates`. Отдельно проверить пустое тело `{}`.

Пример запроса (нет поля `firstname`):

```json
{
  "lastname": "Brown",
  "totalprice": 111,
  "depositpaid": true,
  "bookingdates": {"checkin": "2026-12-01", "checkout": "2026-12-05"}
}
```

## Фактический результат

`500 Internal Server Error`, тело ответа: `Internal Server Error`.

## Ожидаемый результат

`400 Bad Request` с сообщением, какое обязательное поле отсутствует.

## Почему это важно

Клиент не может отличить ошибку пользовательских данных от падения сервера. 500 также поднимает ложные тревоги в мониторинге и логах (ELK/Grafana).

## Тесты-свидетели

- `tests/test_negative.py::test_create_without_required_field[firstname|lastname|totalprice|depositpaid|bookingdates]`
- `tests/test_negative.py::test_create_with_empty_body`

## Предложение по исправлению

Проверять входящую схему на границе API и возвращать 400 со списком невалидных полей; 500 оставить только для реальных сбоев сервера.
